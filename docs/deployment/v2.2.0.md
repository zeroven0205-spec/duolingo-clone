## 2. 环境变量（必做）

### 新增 feature flag

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `FLAG_SHOP_V2` | `off` | Shop v2（积分兑换商品）的总开关。生产建议先 `off`，等回滚演练完成后切 `on`。 |
| `FLAG_XP_BOOST` | `off` | XP Boost 2× 奖励开关。生产建议 `on`，因为这是核心留存机制，但保持可回滚。 |
| `FLAG_REVIEW_QUEUE` | `off` | `/review` 复习队列入口开关。生产建议 `on`，但允许在 bug 时关闭页面。 |

**默认是 OFF**——flag 必须显式 `on` 才启用。`!== "off"` 的语义是反的，已修复。

```bash
# .env / Vercel env
FLAG_SHOP_V2=on
FLAG_XP_BOOST=on
FLAG_REVIEW_QUEUE=on
```

### 不变的依赖

- `DATABASE_URL` — Neon Postgres
- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` / `CLERK_SECRET_KEY`
- `STRIPE_API_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET`
- `NEXT_PUBLIC_POSTHOG_KEY` / `POSTHOG_API_KEY` / `NEXT_PUBLIC_POSTHOG_HOST`

## 3. PWA 上线确认

`next.config.ts` 的 `workboxOptions.runtimeCaching` 现在包含 4 条规则：

| 资源类型 | 策略 | 过期 |
| --- | --- | --- |
| Google Fonts | CacheFirst | 10 entries |
| JS / CSS / woff2 | StaleWhileRevalidate | 7 days, 50 entries |
| `/api/courses\|units\|lessons\|challenges` | StaleWhileRevalidate | 1 hour, 100 entries |
| 图片 (png/jpg/svg/...) | CacheFirst | 30 days, 100 entries |

### 验收步骤

```bash
pnpm build && pnpm start
```

1. Chrome DevTools → Application → Service Workers，确认 SW 已注册（`/sw.js` 或 `@ducanh2912/next-pwa` 的命名）。
2. Network → 勾选 Offline，刷新 `/learn` —— UI 应仍能渲染（字体 / 静态资源 / 课程列表走缓存）。
3. 实时数据（lesson 进度、shop 购买、复习提交）会失败，这是预期 —— 不阻塞用户继续看静态内容。
4. Console 不应有未捕获的 SW 错误。

**不做的事**：Background Sync API、Push Notification、IndexedDB 持久化、课程预下载。这些是 scope creep，已明确剔除。

## 4. Shop / Streak 埋点上线确认

v2.2.0 在三个事件点加上了 PostHog：

| 事件 | 触发位置 | 关键 properties |
| --- | --- | --- |
| `shop_item_purchased` | `actions/shop.ts:chargeAndApply` 成功 | `item_id`, `price`, `points_remaining` |
| `streak_freeze_consumed` | `actions/user-streak.ts:updateStreakAndClaimRewards`（断签被吸收） | `streak_before`, `streak_after` |
| `streak_milestone_reached` | 同上（streak 命中 3 / 7 / 30 / 100 / 365） | `milestone` |

**验收**：在 staging 跑一次完整购买 + 跨天断签流程，去 PostHog dashboard → Activity，确认事件已上报。

**不上报**：`leaderboard_period_viewed` / `streak_celebration_shown` 等 UI-only 事件——会污染分析。

## 5. 复习队列 / 间隔重复 上线确认

### 复习队列（`/review`）

- 入口：`components/user-progress.tsx` 里的 📚 按钮 → `/review`。
- 页面：`app/(main)/review/page.tsx`（server component）
- 交互：`components/review-session.tsx`（client component）
- API：`app/api/review-queue/route.ts`（GET 取到期词，POST 提交结果）

**验收**：
1. staging 跑完至少一节课，让 challenge 完成时把对应的 `user_words` 行写进去。
2. 等几秒，访问 `/review`，应能看到 1 张以上卡片。
3. 点 "记得" / "忘记了" 后，UI 进入下一张，`/api/review-queue` 返回新的 `box` / `easeFactor`。

### 间隔重复 box label（lesson 完成页）

- 位置：`app/lesson/quiz.tsx` 完成态页面底部。
- 显示内容：根据 lesson 整体正确率映射到 Leitner box（100% → Mastered, 75%+ → Known, 50%+ → Familiar, 25%+ → Learning, < 25% → New）。
- 限制：**没有写 per-word 持久化**——这是 UI 暴露，不是真业务逻辑。

**验收**：跑完一节课，result card 下方应看到 "Memory level: Familiar"（或对应 label）。

## 8. 回滚预案

| 改动 | 回滚方式 |
| --- | --- |
| Shop v2 行为 | `FLAG_SHOP_V2=off` 即关闭整个积分兑换流程 |
| XP Boost 2× | `FLAG_XP_BOOST=off` 即回落 10 XP |
| `/review` 页面 | `FLAG_REVIEW_QUEUE=off` 即所有访问 `/review` 的用户重定向到 `/learn` |

| 间隔重复 box label | 删除 `quiz.tsx` 里的 IIFE 块即可，不影响其他逻辑 |

无需数据库回滚——所有 v2.2.0 改动都是向前兼容的。
