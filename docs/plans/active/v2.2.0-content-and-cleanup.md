## 第一性原则

v2.1.0 已上线游戏化机制，但**仓库里有一堆"后端写好了，前端没接通"的半成品**
（`app/api/review-queue` / `db/schema-word-progress.ts` / `lib/spaced-repetition.ts` / `lib/speech评估.ts`）。

v2.2.0 不再开新功能，**只做两件事**：
1. 把 v2.1.0 留的债关掉（XP Boost 实际生效、Hearts Pack 回拉、Shop 埋点、Feature flag）
2. 把已有的后端能力接到前端（复习队列 / 间隔重复 UI）

不引入新语言、不做新题型、不做 CMS 导入——这些都是 scope creep，先把 zh/en 用户手上的体验做扎实。

## P0 — v2.1.0 遗留收尾

### DEBT-1 · XP Boost 实际生效

> ⚠️ **关键修正**：v2.1.0 plan 写的是 `actions/user-progress.ts:completeLesson`，但
> 那个函数只发 PostHog、不动 points。**真正发 XP 的是 `actions/challenge-progress.ts:upsertChallengeProgress`**
> （每次挑战完成 +10，[行 58 / 行 79](actions/challenge-progress.ts)）。

**修改位置**：[actions/challenge-progress.ts](actions/challenge-progress.ts) 中两处 `points: currentUserProgress.points + 10`。

```typescript
// actions/challenge-progress.ts:upsertChallengeProgress
const user = currentUserProgress;
const now = new Date();
const boostActive =
  !!user.xpBoostUntil && user.xpBoostUntil.getTime() > now.getTime();
const xpAward = boostActive ? 20 : 10;
const weeklyStale =
  !user.weeklyResetAt ||
  now.getTime() - user.weeklyResetAt.getTime() > WEEK_IN_MS;
const monthlyStale =
  !user.monthlyResetAt ||
  now.getTime() - user.monthlyResetAt.getTime() > MONTH_IN_MS;

await db
  .update(userProgress)
  .set({
    points: user.points + xpAward,
    pointsWeekly: weeklyStale ? xpAward : user.pointsWeekly + xpAward,
    pointsMonthly: monthlyStale ? xpAward : user.pointsMonthly + xpAward,
    ...(boostActive ? { xpBoostUntil: null } : {}),
  })
  .where(eq(userProgress.userId, userId));
```

**两处都要改**（首次挑战 + 练习模式）。代码重复 OK——两处逻辑差异已经不小，
不要为去重再抽象一层。

### DEBT-2 · Hearts Pack 满血拒绝

```typescript
// actions/shop.ts:applyItemEffect — hearts_pack case
case "hearts_pack": {
  if (user.hearts >= MAX_HEARTS) {
    throw new ShopError("Hearts are already full.");
  }
  await db.update(userProgress)
    .set({ hearts: Math.min(user.hearts + 5, MAX_HEARTS) })
    .where(eq(userProgress.userId, userId));
  return;
}
```

**取消 +5 上限**：v2.1.0 的 `MAX_HEARTS + 5` 是不对的——普通 refill 回到
MAX_HEARTS，pack 应该同理。同时把 items.tsx 里的 disabled 条件加上 `hearts === MAX_HEARTS`。

### DEBT-4 · Feature flag 框架

> ⚠️ **关键修正**：v2.1.0 plan 的默认值反了 (`!== "off"` → 默认 ON)。
> Feature flag 必须**默认 OFF**，否则忘了配就自动开启新功能 = 没 flag。

```typescript
// lib/feature-flag.ts（新建）
export type Flag = "xp_boost" | "shop_v2" | "review_queue";

export function isEnabled(flag: Flag): boolean {
  return process.env[`FLAG_${flag.toUpperCase()}`] === "on";
}
```

只挂两个真需要回滚能力的入口：
- `actions/shop.ts:chargeAndApply` 顶部：`if (!isEnabled("shop_v2")) return { success: false, error: "Shop v2 disabled" };`
- `actions/challenge-progress.ts` XP Boost 分支：`if (isEnabled("xp_boost") && boostActive) { ... }`

不挂 leaderboard / quests / streak——它们都是 v2.1.0 已发布功能，回滚要走正常流程。

```typescript
const due = await fetch(`${process.env.NEXT_PUBLIC_APP_URL}/api/review-queue`, {
```

```typescript
// components/review-card.tsx (新建 client component)
// 单词 + 用户上次答对/答错 → "已掌握" / "再练一次" 按钮 → POST 回 /api/review-queue
```

**接通入口**：`components/user-progress.tsx` 加一个 "📚 复习" 按钮，链接 `/review`。

### WIRE-2 · 间隔重复 UI

**现状**：[lib/spaced-repetition.ts](lib/spaced-repetition.ts) 的 `calculateNextReview` /
`getBoxLabel` 是纯函数，**没有任何调用方**。

最小接通：在 `components/lesson/result-card.tsx` 上，根据用户对当前 challenge 的
对错显示 `getBoxLabel(box)` 标签（如 "Familiar" / "Mastered"）。

不写新的 box 调度逻辑——`calculateNextReview` 是真业务函数，但目前没接口存
box state。这条**只在 UI 上暴露标签**，不动数据。

### WIRE-3 · zh/en 文案校对

**现状**：`messages/en.json` / `messages/zh.json` 都是 115 行，逐字段对照。常见问题：
- zh 漏翻（fallback 到 key 字符串）
- 占位符不对齐（`{name}` 写成 `{0}`）
- 长度差异大导致 UI 溢出

**做法**：
1. 写一个 `scripts/check-i18n.ts` 比对两个 JSON 的 key 一致性，CI 里跑
2. 跑一遍 `/learn` / `/shop` / `/quests` / `/leaderboard` / `/courses`，手记漏翻项
3. 修复，不加新文案

### WIRE-4 · PWA 运行时缓存

> ⚠️ **v1.4.0 审计发现**：[next.config.ts](next.config.ts) 已包装 `@ducanh2912/next-pwa`，
> 但**没传 `runtimeCaching`**。结果：service worker 注册成功，但断网打开应用 = 空白页。
> PWA 名存实亡。

**修改位置**：[next.config.ts:3-8](next.config.ts) 的 `withPWA({...})` 配置块。

```typescript
// next.config.ts
const withPWAConfig = withPWA({
  dest: "public",
  disable: process.env.NODE_ENV === "development",
  register: true,
  cacheStartUrl: true,
  runtimeCaching: [
    {
      urlPattern: /^https:\/\/fonts\.(?:gstatic|googleapis)\.com/,
      handler: "CacheFirst",
      options: { cacheName: "google-fonts", expiration: { maxEntries: 10 } },
    },
    {
      urlPattern: /\.(?:js|css|woff2?)$/,
      handler: "StaleWhileRevalidate",
      options: { cacheName: "static-resources", expiration: { maxEntries: 50, maxAgeSeconds: 7 * 24 * 60 * 60 } },
    },
    {
      urlPattern: /\/api\/(courses|units|lessons|challenges)/,
      handler: "StaleWhileRevalidate",
      options: { cacheName: "course-data", expiration: { maxEntries: 100, maxAgeSeconds: 60 * 60 } },
    },
    {
      urlPattern: /\.(?:png|jpg|jpeg|svg|gif|webp)$/,
      handler: "CacheFirst",
      options: { cacheName: "images", expiration: { maxEntries: 100, maxAgeSeconds: 30 * 24 * 60 * 60 } },
    },
  ],
});
```

**验收**：在 staging 跑 `pnpm build && pnpm start`，DevTools → Application → Service Workers 确认 SW 注册；Network → Offline 重载页面，UI 仍能渲染（字体 / 静态资源走缓存），但 lesson / shop 实时数据会显示"离线"提示（不阻塞用户继续看静态内容）。

**不做的**：
- 后台同步（Background Sync API）
- 推送通知
- 课程内容预下载 / IndexedDB 持久化

这些都是 scope creep，v1.4.0 计划的"完整离线"实际只是"已访问过的页面能缓存"，v2.2.0 把它落地到"至少静态资源 + 课程列表能缓存"。

## 不在本期范围（明确剔除）

下面这些是 ROADMAP 里出现过但 v2.2.0 **不做** 的：

- ❌ 第三种语言（含任何新增语种）
- ❌ 任何新题型（含音频相关）
- ❌ 内容批量导入（安全 + scope 风险）
- ❌ 课程单元扩到 5+（等 v2.2.0 接通复习后看用户真实路径再决定）
- ❌ 视觉 / 交互类打磨（暗色模式、A11y、动画）
- ❌ PWA 完整离线（Background Sync / 推送 / IndexedDB 持久化；runtimeCaching 在 P1）
- ❌ AI / 移动端 / 社交

理由：
- **新语言 / 新题型**：先把现有 zh/en 体验 + SELECT/ASSIST 题型的留存数据做出来，再决定扩张方向
- **批量导入**：admin 鉴权层尚未建立
- **视觉 / 动画**：审美问题不是产品问题
